# دليل نشر موقع نخلة على Netlify

المجلد مكتفٍ ذاتياً بالكامل: يمكن قصّه ونسخه إلى أي مكان على القرص، وكل شيء يعمل بعده (الواجهة، نموذج الحجز، الخادم المحلي، الاختبارات).

---

## ١) البنية

| المسار | الغرض |
|---|---|
| `src/` | الواجهة (React + Vite + Tailwind) |
| `netlify/functions/booking.ts` | دالة الحجز الموقِّعة (تُنشر تلقائياً مع الموقع) |
| `netlify.toml` | إعدادات النشر: `npm run build` → `dist` |
| `external-backend/apps-script/` | نسخة نخلة من النظام الخارجي (بريد باسم «عيادات نخلة») |
| `scripts/demo-runtime.mjs` | الخادم المحلي للتجربة (`npm run dev`) |
| `tests/booking-flow.test.mjs` | اختبار التدفق ثنائي الطور (node --test) |
| `demo-mail.local.json` | بيانات SMTP للتجربة المحلية — **سرّي، لا يُرفع أبداً** (مستثنى في .gitignore) |

## ٢) خطوات النشر

1. **البناء المحلي** (للتحقق قبل الرفع):
   ```
   npm install
   npm run build
   ```
   الناتج: مجلد `dist/` (ملف واحد + الصور).

2. **الرفع إلى Netlify** — إحدى طريقتين:
   - **سحب وإفلات**: افتح app.netlify.com/drop واسحب مجلد `dist` — يعمل فوراً، لكن **بدون دالة الحجز** (الدوال تحتاج ربط Git أو CLI).
   - **الطريقة الكاملة (الموصى بها)**: ارفع المجلد إلى مستودع Git خاص به، ثم في Netlify: *Add new site → Import an existing project* → اختر المستودع. سيقرأ Netlify `netlify.toml` تلقائياً (أمر البناء ومجلد النشر ومسار الدوال).

3. **متغيرات البيئة** (لوحة Netlify → Site configuration → Environment variables — نطاق Functions):

   | المتغير | القيمة |
   |---|---|
   | `NAKHLA_EXEC_URL` | رابط `…/exec` لنشر Apps Script الخاص بنخلة (نسخة `external-backend/apps-script/`) |
   | `NAKHLA_INGEST_SECRET` | سر عشوائي URL-safe بطول 43–128 حرفاً |

   بدون هذين المتغيرين سيرد النموذج برسالة «الموقع غير مربوط بجدول الاستقبال بعد» — الواجهة تعمل لكن الإرسال معطّل. (الأسماء `NAKHLA_` خاصة بموقع نخلة ومستقلة تماماً عن أي عيادة أخرى؛ كل نسخة من الموقع — مجمع أو مركز — تحتاج سكربت Apps Script خاصاً بها وسرّاً خاصاً بها حتى لا تتشابك حجوزاتها.)

4. **نشر نظام البريد الخارجي** (رسالة الاستلام + رسالة المتابعة):
   - أنشئ مشروع Google Apps Script جديداً وانسخ إليه ملفات `external-backend/apps-script/` الستة (`Config.gs, Domain.gs, Storage.gs, Api.gs, Worker.gs, Admin.gs`) — هذه نسخة نخلة: كل رسائلها بعنوان «عيادات نخلة» وتوقيع «Nakhla Dental DEMO».
   - انشرها كتطبيق ويب (Anyone) واضبط `SPREADSHEET_ID` و`ALLOWED_EMAILS` و`INGEST_SECRET` من خصائص السكربت، ثم ضع رابط `/exec` في `NAKHLA_EXEC_URL` أعلاه.

## ٣) لماذا تصل الرسائل إلى Spam؟ (والحل الإنتاجي)

**السبب**: في وضع التجربة المحلي تُرسل الرسائل عبر SMTP شخصي (Gmail + كلمة مرور تطبيقات) بلا نطاق أعمال مُوثّق. مزودات البريد (Gmail/Outlook) تصنّف رسائل المُرسلين الشخصيين الآليين كغير موثوقة لأن:
- لا يوجد نطاق أعمال بتاريخ إرسال، وSPF/DKIM/DMARC غير مضبوطة لنطاق العيادة،
- عنوان المُرسل (gmail.com) لا يطابق نطاق موقع العيادة،
- الرسائل نصية بسيطة بلا تواقيع دومين.

**الحل الإنتاجي** (لا يمكن تجاوزه بالشيفرة — هو مسألة نطاق وسمعة مُرسل):
1. استخدم مزوّد بريد معاملات (Amazon SES / SendGrid / Mailgun / Postmark / Resend) بنطاق مُوثّق للعيادة (مثل `mail.nakhla-dental.sa`).
2. أضف سجلات DNS: **SPF** و**DKIM** و**DMARC** التي يطلبها المزوّد عند توثيق النطاق.
3. اجعل عنوان المُرسل على النطاق الموثّق نفسه (مثل `no-reply@nakhla-dental.sa`) مع `Reply-To` لصندوق العيادة.
4. ابدأ بحجم إرسال صغير وتزايد تدريجياً (warm-up)، وأرسل فقط لمن وافق على التواصل — نموذج الحجز يسجّل الموافقة الصريحة أصلاً.

بعد ذلك تصل الرسائل إلى صندوق الوارد وليس Spam.
